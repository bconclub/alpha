## What Is Alpha
Alpha is a precision momentum-trading bot built by Z at BCON Club. It currently trades **crypto options on Delta Exchange India** (BTC + ETH). The engine still carries code for Bybit, Kraken Futures, and Binance, but the live deployment is **Delta-only options** while those exchanges are disabled. The mission: grow capital through quality trades that beat the fees.

## Trading Logic

### Signal Generation (scalp.py — v6.3)
Every tick, the scalp engine evaluates 12 independent signals. Each signal fires a bull or bear tag.

| # | Signal | Tag | Detection Logic |
|---|--------|-----|----------------|
| 1 | **Momentum** | `MOM:` | 0.12%+ price move in last 60s |
| 2 | **Volume Spike** | `VOL:` | 0.8x+ average volume (pair-adjusted) |
| 3 | **RSI Extreme** | `RSI:` | RSI < 40 (long) or > 60 (short) |
| 4 | **Bollinger Band** | `BB:` | Price outside BB + mean-reversion setup |
| 5 | **5m Momentum** | `MOM5M:` | Sustained 5-candle trend confirmation |
| 6 | **Trend Continuation** | `TCONT:` | New 15-candle extreme + volume |
| 7 | **VWAP Reclaim** | `VWAP:` | Price above VWAP + 9 EMA > 21 EMA ribbon |
| 8 | **BB Squeeze** | `BBSQZ:` | BB inside Keltner Channel → breakout + volume |
| 9 | ~~**Liquidity Sweep**~~ | ~~`LIQSWEEP:`~~ | **DISABLED** — poor performance |
| 10 | **Fair Value Gap** | `FVG:` | 3-candle imbalance gap + price filling |
| 11 | **Volume Divergence** | `VOLDIV:` | Price vs volume trend divergence |
| 12 | **BPRC** | `BPRC:` | Breakout Pullback Reload Continue pattern |

### BB Squeeze Entry Flow (options_scalp.py)
The primary entry method. One position at a time across BTC+ETH.

1. **Squeeze Detection** — BB width < 0.7% (BTC) / 1.0% (ETH) + BB inside KC
2. **Direction Bias** — bb_position < 0.4 → CALL, bb_position > 0.6 → PUT, middle → cheaper leg
3. **Cheap Premium** — Track 30-min premium range, buy in bottom 25%
4. **Confidence Score** — tightness × cheapness × volume, skip if < 0.6, BTC gets 0.7× penalty
5. **Expiry** — nearest daily, min 1h away; switch when < 3h remain
6. **Limit Entry** — place at cheap threshold, poll 5 min for fill
7. **No-fill** — cancel, wait for next squeeze (no cooldown)

### Momentum Burst Entry Flow (options_scalp.py)
Secondary entry mode when not in squeeze, designed for immediate momentum participation.

1. **Underlying Momentum Gate** — 60s momentum magnitude must be at least 0.15%
2. **Premium Confirmation (Sustained)** — ATM premium must rise for 2 consecutive ticks:
   - CALL path: `current_call_ask > prev_call_ask > prev2_call_ask`
   - PUT path: `current_put_ask > prev_put_ask > prev2_put_ask`
3. **Direction**
   - `momentum_60s > 0` + sustained call ask rise -> buy CALL
   - `momentum_60s < 0` + sustained put ask rise -> buy PUT
4. **Entry Timing** — no confirmation window; enters immediately once all checks pass

### Options Exit System (`options_scalp.py`)

Authoritative list of **market exit** reasons from `_check_option_exit` → `_do_option_exit` (GPFC #31 / #32):

| `exit_type` | When it fires |
|-------------|----------------|
| `EXPIRED_WORTHLESS` | `current_premium <= 0` and wall-clock is at/after `expiry_dt` |
| `OPT_HARD_SL` | Premium PnL from entry **≤ -30%** |
| `EXPIRY_DEAD` | **< 8h** to expiry (`EXPIRY_MODE_HOURS`), PnL **< -20%**, held **> 120s** |
| `OPT_TRAIL` | Trailing latched once **current** PnL from entry **≥ +10%**; premium falls below `highest_premium × (1 − trail%)` while still in profit; trail **%** comes from `OPT_TRAIL_TIERS` by **peak** PnL |
| `OPT_PEAK_TRAIL` | Still in profit with trail active; gave back **≥ `PULLBACK_EXIT_PCT` (40%)** of **peak dollar gain** (`highest − entry`) after peak **≥ `PULLBACK_ACTIVATE_PCT` (+8%)** |
| `OPT_ENERGY_WINNER_FADING` | `energy_score` below dead threshold for **≥ 3** sustained low-energy ticks, PnL **> 0**, **peak_pnl_pct > +20%** |

**Synthetic / DB-close paths** (`_handle_position_gone`, `metadata.exit_type` like `POSITION_GONE_TICKER_FAIL_REPEATED`, `EXPIRY_EXPIRED_TICKER_FAIL`, etc.): repeated option ticker failures, or ticker failure inside the final **5** minutes before expiry — see source around `_check_option_exit` ticker `except` and `_handle_position_gone`.

**Removed in GPFC #32 (v0.22.4):** `OPT_RATCHET_DYNAMIC` (ratchet floor exit) and `OPT_ENERGY_DEAD_LOSER`. **`_compute_dynamic_floor` / `_opt_ratchet_floor`** still run for heartbeat logging and position-state writes; they are **not** exit gates anymore.

**Constants present but not automated exits in `_check_option_exit` today:** `TP_PREMIUM_GAIN_PCT` (dashboard `tp_price` hint only), `EXPIRY_GUARD_*`, progressive stale ladder numbers, `DECAY_THRESHOLD_PCT`, `PHASE1_HANDS_OFF_SEC`. The module docstring may still name legacy exits (`OPT_ENTRY_DROP`, `OPT_STALE`, etc.).

#### Tiered trail reference (`OPT_TRAIL_TIERS`)

Trail **distance** (below `highest_premium`) tightens as **peak** PnL rises:

| Peak PnL | Trail distance |
|----------|----------------|
| +10% | 8% |
| +20% | 6% |
| +30% | 5% |
| +50% | 4% |

#### Energy confirmation (`OPT_ENERGY_WINNER_FADING` only)

- `_low_energy_ticks` counts consecutive ticks with `energy_score` below the dead threshold.
- **`OPT_ENERGY_WINNER_FADING`** requires **≥ 3** such ticks (plus positive PnL and peak > +20%).

### Options Sizing (GPFC #20)
**Fixed 20-30% capital allocation per trade** (replaced confidence-based multipliers).

- **Allocation formula**: `20% + (confidence × 10%)` = 20-30% range
- **Low confidence (0.6)**: ~26% of capital
- **High confidence (1.0)**: 30% of capital
- **Collateral**: Premium paid = allocation × balance
- **Contracts**: `collateral / (premium × multiplier)`
- **Safety caps**:
  - Never exceed available balance
  - SL loss never > 25% of balance
  - ETH hard cap: 40 contracts
  - Survival mode (< $5): max 5 contracts

## Live Position State
The engine writes position state to the DB every ~10 seconds while a position is open:
- **`position_state`**: `'holding'` or `'trailing'`
- **`current_pnl`**: Unrealized P&L %
- **`peak_pnl`**: Highest P&L % reached
- **`current_price`**: Latest premium seen

Dashboard reads via `v_open_positions` view with 3-second live price polling overlay.

- **options_scalp** — Active options buying on Delta Exchange (BB Squeeze + momentum burst entries, 20–30% sizing, tiered trail / peak trail, hard SL, expiry-mode dead-loser exit, energy winner-fading exit)

Inactive/disabled: `futures_momentum`, `momentum`, `grid`, `arbitrage`, `strategy_selector`

## Key Protections
- **Global position lock**: only 1 option position at a time across BTC+ETH
- **Options entries**: dynamic breakout path does not add a mandatory no-fill cooldown (see `options_scalp.py`); cooldown machinery remains for compatibility
- **Position-gone detection**: verifies exchange positions every ~30s; logs when missing (does not emit a market exit from verify alone); ticker-failure handler can synthesize `POSITION_GONE_*` / `EXPIRY_*` closes
- **Orphan protection**: per-exchange reconciliation every 60s
- **Expiry handling**: `EXPIRY_DEAD` for deep losers inside expiry window; `EXPIRED_WORTHLESS` when premium is zero at/after expiry; `EXPIRY_GUARD_*` constants exist but are not wired as separate automated exits in `_check_option_exit` today
- **Stale ladder constants**: defined on the strategy class for squeeze hold windows / future work; no `OPT_STALE` exit is emitted from `_check_option_exit` in the current build
- **Telegram resilience**: Auto-reconnect on failure + health check + clean shutdown
- **WebSocket price feed**: Per-exchange WS for sub-second monitoring
- **Capital utilization logging**: Logs % deployed every 10 ticks (~50s)
