# Alphabot — Build Truth

## What Is Alpha
Alpha is a precision momentum-trading bot built by Z at BCON Club. It currently trades **crypto options on Delta Exchange India** (BTC + ETH). The engine still carries code for Bybit, Kraken Futures, and Binance, but the live deployment is **Delta-only options** while those exchanges are disabled. The mission: grow capital through quality trades that beat the fees.

## Trading Logic

### Signal Generation (scalp.py — v6.3)
Every tick, the scalp engine evaluates 12 independent signals. Each signal fires a bull or bear tag.

| # | Signal | Tag | Detection Logic |
|---|--------|-----|----------------|
| 1 | **Momentum** | `MOM:` | 0.12%+ price move in last 60s |
| 2 | **Volume Spike** | `VOL:` | 0.8x+ average volume (pair-adjusted) |
| 3 | **RSI Extreme** | `RSI:` | RSI < 40 (long) or > 60 (short) |
| 4 | **Bollinger Band** | `BB:` | Price outside BB + mean-reversion setup |
| 5 | **5m Momentum** | `MOM5M:` | Sustained 5-candle trend confirmation |
| 6 | **Trend Continuation** | `TCONT:` | New 15-candle extreme + volume |
| 7 | **VWAP Reclaim** | `VWAP:` | Price above VWAP + 9 EMA > 21 EMA ribbon |
| 8 | **BB Squeeze** | `BBSQZ:` | BB inside Keltner Channel → breakout + volume |
| 9 | ~~**Liquidity Sweep**~~ | ~~`LIQSWEEP:`~~ | **DISABLED** — poor performance |
| 10 | **Fair Value Gap** | `FVG:` | 3-candle imbalance gap + price filling |
| 11 | **Volume Divergence** | `VOLDIV:` | Price vs volume trend divergence |
| 12 | **BPRC** | `BPRC:` | Breakout Pullback Reload Continue pattern |

### BB Squeeze Entry Flow (options_scalp.py)
The primary entry method. One position at a time across BTC+ETH.

1. **Squeeze Detection** — BB width < 0.7% (BTC) / 1.0% (ETH) + BB inside KC
2. **bb_kc_ratio guard (GPFC #65)** — at squeeze break, if `bb_width_pct / kc_width_pct > 2.0` → `SQUEEZE_SKIP`. BB has already expanded to twice the KC width — this is post-breakout chasing, not compression.
3. **Direction Bias** — direction inferred from which BB band exited KC (UP/DOWN); bb_position used for cheaper-leg selection
4. **Cheap Premium** — Track 30-min premium range, buy in bottom 25%
5. **Confidence Score** — tightness × cheapness × volume, skip if < 0.6, BTC gets 0.7× penalty
6. **Expiry** — nearest daily, min 1h away; switch when < 3h remain
7. **Entry-quality filter (GPFC #67)** — turnover ≥ $2M, |delta| ∈ [0.40, 0.65], mark_vol ≥ 0.40 on the chosen strike's ticker; else `ENTRY_QUALITY_SKIP`
8. **Dynamic confirmation window** — velocity-tiered (20s / 40s / 60s) wait after breakout detection; checks `BREAKOUT_FAKEOUT` (drop > 5%) and `BREAKOUT_OVERPRICED` (rise > 15%) before firing
9. **Limit Entry** — place at confirmed ask, poll 5 min for fill
10. **No-fill** — cancel, wait for next squeeze (no cooldown)

### Momentum Burst Entry Flow (options_scalp.py)
Secondary entry mode when not in squeeze, designed for immediate momentum participation.

1. **Underlying Momentum Gate** — `MOMENTUM_BURST_THRESHOLD_PCT` = **0.05%** (GPFC #66; was 0.20% pre-#65). 60s momentum magnitude must clear this floor.
2. **Premium Confirmation (Sustained)** — ATM premium must rise for 2 consecutive ticks (`MOMENTUM_BURST_MIN_ASK_RISE_PCT` = 1.5% cumulative):
   - CALL path: `current_call_ask > prev_call_ask > prev2_call_ask`
   - PUT path: `current_put_ask > prev_put_ask > prev2_put_ask`
3. **Freshness gate** — `mom_20s / mom_60s ≥ 0.50` (move concentrated in the recent 20s, not a fading tail).
4. **Continuation gate** — recent 20s momentum sign must match the 60s sign (move not already reversing).
5. **Regime alignment** — 5min trend must not be counter to the option side (≥ ±0.10% counter-trend blocks entry).
6. **Spread guard** — bid/ask spread > 8% on the chosen strike → skip.
7. **Entry-quality filter (GPFC #67)** — turnover ≥ $2M, |delta| ∈ [0.40, 0.65], mark_vol ≥ 0.40, else `ENTRY_QUALITY_SKIP`.
8. **Direction**
   - `momentum_60s > 0` + sustained call ask rise → buy CALL
   - `momentum_60s < 0` + sustained put ask rise → buy PUT
9. **Entry Timing** — no confirmation window; enters immediately once all checks pass.

### Options Exit System (`options_scalp.py`) — post GPFC #67

Authoritative exit-priority order from `_check_option_exit` → `_do_option_exit`. **No time-based gates anywhere in this list** — every gate is state-based (price, peak, momentum, spot direction). Time-gate constants `OPT_HARD_MAX_HOLD_HOURS`, `PHASE_BREATHING_SEC`, `EXPIRY_GUARD_*`, age-based `_dynamic_sl_pct`, and the entire `_thesis_broken` / STALLED ladder were deleted in GPFC #60 round 2.

| Order | `exit_type` | When it fires |
|-------|-------------|----------------|
| 0 | `EXPIRED_WORTHLESS` | `current_premium <= 0` and wall-clock is at/after `expiry_dt` |
| 1 | `DEAD` (GPFC #67) | **All three** required: `peak ≤ +0.5%` **AND** `premium ≤ -8%` **AND** signed underlying 60s momentum > 0.05% **against** the position. Saves the bleed from -8% → -15% on dead-on-arrival entries. |
| 2 | `STOP` | Premium PnL from entry ≤ **`SL_PREMIUM_LOSS_PCT` = -15%**. Flat — no age tightening. |
| 3 | `OPT_TRAIL` | Trail arms once `peak_pnl_pct ≥ 4%`. Exit if `current_premium < entry_premium × (1 + tier_floor_pct/100)`. **`PULLBACK_SPOT_VETO_PCT` = 0.10** (GPFC #64): if signed underlying 60s momentum is still ≥ 0.10% in our direction, defer the TRAIL exit. |
| 4 | `OPT_PEAK_TRAIL` | Same activation (peak ≥ 4%). Fires when `(highest − current) / (highest − entry) ≥ PULLBACK_EXIT_PCT (30%)` confirmed for `PULLBACK_CONFIRMATION_TICKS` (1 tick if peak ≥ 10%, else 2). Same spot-direction veto applies. |
| 5 | `OPT_BREAKEVEN_STOP` | Once `peak_pnl_pct ≥ BREAKEVEN_STOP_ACTIVATE_PCT (8%)`, exit if `premium_change_pct ≤ BREAKEVEN_STOP_EXIT_PCT (0.5%)`. Converts would-be losers (peak +10% → -12%) into scratches. |

**Spot-direction veto helper (`_underlying_still_supports_position`)** wraps `_underlying_momentum_pct()` with our_dir sign. Returns `(supports, aligned_pct)`. Only `OPT_TRAIL` and `OPT_PEAK_TRAIL` consult it. `STOP`, `DEAD`, and `OPT_BREAKEVEN_STOP` always fire when their conditions are met.

**Synthetic / DB-close paths** (`_handle_position_gone`): repeated option ticker failures, or ticker failure inside the final 5 minutes before expiry (`_EXPIRY_CLOSE_MINUTES = 5`). These are the only worthless-expiry safeguards remaining post-#60 (the `EXPIRY_GUARD_*` class constants were deleted as time-gates).

**Removed (cumulative):**
- GPFC #32: `OPT_RATCHET_DYNAMIC`, `OPT_ENERGY_DEAD_LOSER`
- GPFC #60 r2: `TIMEOUT` (4h max-hold), `STALLED` (layered age patience), breathing-window gating, `OPT_ENERGY_WINNER_FADING`
- GPFC #63: `MOM_DEATH` (premium-velocity death detector — was killing winners that gave back during early IV crush)

#### Tiered trail reference (`OPT_TRAIL_TIERS`) — GPFC #63/#67

Format: `(peak_threshold_pct, exit_floor_pct)` where the floor is **absolute % from entry** (rewritten in #62 from "% below peak"). Once peak hits a threshold, exit if pnl drops below the floor:

| Peak hit | Floor locks at |
|----------|----------------|
| +4% | +1% |
| +8% | +4% |
| +12% | +7% |
| +18% | +12% |
| +25% | +18% |
| +40% | +30% |
| +60% | +48% |
| +100% | +85% |

Lookup: `_opt_trail_floor_pct(peak_pnl_pct)`. Trail block gates on `peak_pnl_pct >= OPT_TRAIL_TIERS[0][0]` (= 4%).

#### Regime classifier (`_classify_regime`, log-only)

Computed each tick (cached 30s). Returns one of `TRENDING_UP` / `TRENDING_DOWN` / `CHOPPY` / `UNKNOWN`. The `DEAD` bucket was deleted in GPFC #63 alongside `MOM_DEATH`. Inputs: last-5 candle close-open sign sum, ATR-now vs 20-bar mean, BB-inside-KC. **Not currently a gate** — captured into `trades.metadata.regime` for post-mortem until 30+ regime-tagged trades are accumulated.

#### Entry-signal capture (`_capture_entry_signals`, GPFC #60 r2 + #61)

At every entry, snapshot to `trades.metadata` jsonb column: `iv` (mark_vol), `iv_24h` (mark_change_24h), `oi`, `oi_value_usd`, `oi_change_6h`, `turnover_usd`, greeks (`delta`, `gamma`, `theta`, `vega`), `bb_width_pct`, `kc_width_pct`, `breakout_velocity_pct`, `premium_velocity_at_entry`, `underlying_mom_60s`, `regime`, `spot_at_entry`.

### Options Sizing (GPFC #20)
**Fixed 20-30% capital allocation per trade** (replaced confidence-based multipliers).

- **Allocation formula**: `20% + (confidence × 10%)` = 20-30% range
- **Low confidence (0.6)**: ~26% of capital
- **High confidence (1.0)**: 30% of capital
- **Collateral**: Premium paid = allocation × balance
- **Contracts**: `collateral / (premium × multiplier)`
- **Safety caps**:
  - Never exceed available balance
  - SL loss never > 25% of balance
  - ETH hard cap: 40 contracts
  - Survival mode (< $5): max 5 contracts

## Live Position State
The engine writes position state to the DB every ~10 seconds while a position is open:
- **`position_state`**: `'holding'` or `'trailing'`
- **`current_pnl`**: Unrealized P&L %
- **`peak_pnl`**: Highest P&L % reached
- **`current_price`**: Latest premium seen

Dashboard reads via `v_open_positions` view with 3-second live price polling overlay.

## Key Protections
- **Global position lock**: only 1 option position at a time across BTC+ETH
- **Options entries**: dynamic breakout path does not add a mandatory no-fill cooldown
- **Entry quality (GPFC #67)**: turnover ≥ $2M, |delta| ∈ [0.40, 0.65], mark_vol ≥ 0.40 — applied on both squeeze and MB paths before the order placement
- **Squeeze post-breakout filter (GPFC #65)**: `bb_kc_width_ratio > 2.0` at squeeze break → `SQUEEZE_SKIP` (block chasing trades that already broke out)
- **Spot-direction veto (GPFC #64)**: `OPT_TRAIL` and `OPT_PEAK_TRAIL` defer if signed underlying 60s momentum still ≥ 0.10% in our direction. `STOP`, `DEAD`, `BREAKEVEN` always fire.
- **Position-gone detection**: verifies exchange positions every ~30s; logs when missing (does not emit a market exit from verify alone); ticker-failure handler can synthesize `POSITION_GONE_*` / `EXPIRY_*` closes
- **Orphan protection**: per-exchange reconciliation every 60s
- **Expiry handling**: `EXPIRED_WORTHLESS` when premium is zero at/after expiry; `_EXPIRY_CLOSE_MINUTES = 5` ticker-failure synthetic close inside the final 5 minutes. `EXPIRY_GUARD_*` class constants and the time-based `OPT_HARD_MAX_HOLD_HOURS` were deleted in GPFC #60 round 2.
- **Telegram resilience**: Auto-reconnect on failure + health check + clean shutdown
- **WebSocket price feed**: Per-exchange WS for sub-second monitoring
- **Capital utilization logging**: Logs % deployed every 10 ticks (~50s)
